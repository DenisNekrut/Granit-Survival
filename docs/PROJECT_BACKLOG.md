# Granit Survival — журнал требований и выполнения

**Правило проекта:** каждое новое требование пользователя заносится в этот файл до начала реализации. Пункт не удаляется после выполнения: меняется статус, добавляются PR/коммиты и результат проверки.

**Последнее обновление:** 2026-11-18  
**Основная платформа:** Android, альбомная ориентация  
**Движок:** собственный Granit Engine на Kotlin/JVM + Android SDK + EGL14/OpenGL ES 2.0. Unity, Godot и MonoGame не использовать.

## Легенда статусов

- `BACKLOG` — требование записано, разработка ещё не начата.
- `IN PROGRESS` — выполняется.
- `REVIEW` — реализация готова, ждёт проверки/слияния.
- `DONE` — реализация и необходимые автоматические проверки завершены.
- `DEVICE TEST` — требуется ручная проверка на Android-устройстве.
- `BLOCKED` — есть конкретная блокирующая причина.

## Правила ведения

1. Все новые пожелания и уточнения пользователя фиксируются здесь.
2. У каждой задачи есть ID, приоритет, статус и критерий готовности.
3. Изменения ведутся в feature-ветках и Pull Request; `main` не изменяется напрямую.
4. PR не считается завершённым только потому, что код написан: нужны CI и проверка diff.
5. Успешный CI не означает, что приложение проверено на физическом телефоне.
6. Завершённые задачи остаются в журнале; история выполнения не стирается.
7. Перед новой итерацией сверять этот файл, открытые PR и результаты Actions.

## История требований пользователя

### 2026-11-18 — интерфейс, сохранения и визуальная переработка
Пользователь потребовал:
- вести единый файл, куда заносится каждое его пожелание и отслеживается выполнение;
- добавить главное меню с настройками и сохранениями;
- переработать 2D-модельки;
- продолжить разработку.

Эти требования зарегистрированы как GS-007—GS-013. Главное меню, настройки и менеджер сохранений должны быть отдельными экранами/состояниями, а не просто декоративными кнопками поверх игрового экрана.

4. Создать Sprite/Atlas pipeline и заменить блочные заглушки согласованным набором 2D-спрайтов.
5. Добавить тесты, проверить CI и подготовить APK для ручной проверки.
