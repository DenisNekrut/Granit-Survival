# Granit Engine — архитектура v2.0

**Статус:** утверждённое техническое направление для Granit Survival  
**Платформа первого релиза:** Android, альбомная ориентация  
**Движок:** собственный, с нуля. Unity, Godot и MonoGame не используются.

## 1. Принципиальное решение

Granit Engine — собственный 2D-движок, который реализуется в коде проекта. Android SDK используется только как платформенный слой: жизненный цикл приложения, окно, поверхность, сенсорный ввод и файловая система. EGL14 и OpenGL ES 2.0 используются как низкоуровневые графические API, а не как готовый игровой движок.

Основной язык — Kotlin/JVM. Архитектура Android-first должна позволять в будущем добавить desktop backend, не смешивая его с игровой логикой.

## 2. Слои архитектуры

### 2.1 Platform Android
- MainActivity — запуск, системные события и ориентация.
- GameSurface — SurfaceView и связь с поверхностью Android.
- EglContext — создание и освобождение EGL-контекста.
- AndroidInput — преобразование касаний в события движка.
- AndroidStorage — доступ к внутреннему каталогу приложения.

Платформенный код не содержит правил игрового процесса.

### 2.2 Granit Engine Core
- Engine — запуск и остановка подсистем.
- GameLoop — отдельный поток, фиксированный шаг симуляции и ограничение накопленного времени.
- Time — delta time, игровой такт и пауза.
- EventBus — типизированные события между подсистемами.
- EngineConfig — виртуальное разрешение, масштабирование и настройки.

### 2.3 Graphics
- Renderer2D — отрисовка примитивов и спрайтов.
- Camera2D — преобразование мировых координат в экранные.
- Texture и Sprite — текстуры и области спрайтов.
- TileMapRenderer — отрисовка тайлов.
- PixelPerfect — nearest-neighbor фильтрация и целочисленное масштабирование, где возможно.
- DebugOverlay — FPS и диагностические показатели.

Первый этап использует OpenGL ES 2.0 и простой placeholder-art. Сложные эффекты и редактор уровней не входят в начальный MVP.

### 2.4 Input
- Нормализованные события PointerDown, PointerMove, PointerUp.
- Поддержка нескольких одновременных касаний.
- Виртуальный джойстик и экранные кнопки поверх общего API ввода.
- Игровая логика не зависит от Android MotionEvent.

### 2.5 World и игровые объекты
- Scene — жизненный цикл игровой сцены.
- Entity — объект мира.
- Component — подключаемые компоненты.
- Transform2D — позиция, поворот и масштаб.
- Collider2D — простые прямоугольные и круглые коллайдеры.
- World — обновление объектов, столкновения и запросы взаимодействий.

На старте используется минимальная компонентная модель, без сложного ECS и преждевременной оптимизации.

### 2.6 UI, Audio, Assets, Save
- UiCanvas — экранные элементы и hit-testing.
- AudioSystem — абстракция воспроизведения коротких звуков.
- AssetManager — загрузка и кеширование ресурсов.
- SaveStore — версионированная сериализация состояния в JSON во внутреннее хранилище Android; запись через AtomicFile, список/загрузка/удаление слотов.
- SettingsStore — хранение настроек игрока в SharedPreferences через платформенный адаптер.
- Diagnostics — логирование ошибок и состояния движка.

## 3. Разделение Engine и Game

Движок отвечает за общие механизмы. Модуль Granit Survival реализует правила конкретной игры.

## 4. Игровая архитектура Granit Survival

- PlayerSystem — движение и состояние персонажа.
- InventorySystem — сетка инвентаря 4×4 и предметы.
- SurvivalSystem — здоровье, голод, жажда и энергия.
- WorldTimeSystem — игровое время, сон и начало нового дня.
- PsychologySystem — стресс, одиночество, усталость и мораль.
- LibrarySystem — книги, чтение, знания и рецепты.
- CraftingSystem — рецепты и создание предметов.
- BunkerSystem — безопасная зона, хранение и улучшения.
- ExpeditionSystem — выходы в мир и возвращение.
- CheckpointSystem — контрольная точка при пробуждении перед вылазкой.

### Правило контрольной точки

Автосохранение выполняется при пробуждении перед вылазкой. При неудачной вылазке загружается именно эта контрольная точка. Временные изменения после пробуждения откатываются целиком: время, предметы, ресурсы, состояние мира и психологические показатели. Знания и рецепты, полученные после контрольной точки, также откатываются, если персонаж не вернулся и не закрепил прогресс следующим успешным сохранением.

## 5. Порядок разработки

| Этап | Результат | Критерий готовности |
|---|---|---|
| 0. Bootstrap | Android shell, SurfaceView, EGL, render thread, сенсорный ввод | Приложение создаёт и освобождает поверхность корректно |
| 1. Core loop | Fixed timestep, очистка экрана, Renderer2D, FPS | Тестовая сцена работает без зависаний при pause/resume |
| 2. Pixel renderer | Камера, координаты, текстуры, nearest sampling | Тестовая карта и спрайт отображаются без размытия |
| 3. World/player | Tilemap, игрок, коллизии, камера | Персонаж перемещается по тестовой карте |
| 4. Interaction | Сенсорный ввод, джойстик, действие | Управление работает при одновременных касаниях |
| 5. Inventory | Предметы и UI 4×4 | Подбор и отображение предметов |
| 6. Survival/time | Показатели, время, сон, новый день | Состояния корректно обновляются |
| 7. Checkpoint/save | JSON-сохранение и откат к пробуждению | Перезапуск и тестовый откат восстанавливают ожидаемое состояние |
| 8. Psychology/library | Четыре показателя, чтение, знания | Эффекты и откат знаний соответствуют правилам |
| 9. Bunker/crafting | Верстак, рецепты, развитие убежища | Предметы создаются при наличии ресурсов |
| 10. Expedition | Зоны, ресурсы, события и возврат | Работает полный базовый игровой цикл |
| 11. Release | Аудио, настройки, оптимизация, Android package | Установка и тест на целевом устройстве |

Этапы выполняются последовательно. Следующий этап не объявляется готовым, пока критерии текущего не проверены.

## 6. Технические ограничения и качество

- Не подключать готовый игровой движок или framework, подменяющий Granit Engine.
- Все GL-команды выполняются в render thread с активным EGL-контекстом.
- Корректно переживать потерю и пересоздание Android Surface/EGL context.
- Симуляция использует фиксированный timestep; отрисовка может идти с отдельной частотой.
- Координаты игры задаются в виртуальных мировых единицах, а не в физических пикселях экрана.
- Сохранения версионируются через saveVersion и записываются атомарно.
- Сначала создаётся минимальный работающий вертикальный срез, затем расширяются системы.
- Не заявлять о сборке или тестировании, пока проверки реально не выполнены.

## 8. Реализовано в текущем прототипе (обновление 2026-11-19)

- Собственный Android-first runtime на Kotlin/JVM, SurfaceView, EGL14 и OpenGL ES 2.0.
- Четыре связанные зоны с проверяемой достижимостью выходов, отдельными картами и сохранением ресурсов по зонам.
- Инвентарь, хранилище, сбор ресурсов, стоимость времени действий, сон и wake-up rollback.
- JSON save schema v6: три ручных слота, отдельный autosave, чтение старых форматов v1–v4.
- Главное меню, пауза, менеджер сохранений, настройки, хранилище и мастерская.
- Крафт бинта и аптечки; рецепт аптечки открывается техническим руководством.
- Библиотека из пяти категорий книг и ежедневные радиосообщения в убежище.
- Психологические показатели с учётом времени, сна, движения и смены зон; состояние сохраняется и откатывается.
- PixelSpriteAtlas, idle/walk персонажа, спрайты ресурсов и медицинских предметов, отдельная отрисовка окружения четырёх зон.

### Не завершено
- Полный art pass, внешние sprite sheets, анимации окружения и визуальная проверка на телефоне.
- Дополнительные рецепты и улучшения убежища, погодные и сюжетные события, NPC и цели экспедиций.
- Полное подключение громкости, вибрации и качества графики.
- Физическое Android-тестирование, оптимизация FPS и проверка энергопотребления.
